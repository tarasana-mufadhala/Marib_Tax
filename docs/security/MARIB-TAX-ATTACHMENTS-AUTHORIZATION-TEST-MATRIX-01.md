# مصفوفة اختبارات تفويض المرفقات 01

**الحالة:** أساس أمني للاختبار فقط — لا اتصال بقاعدة بيانات أو تخزين

**النطاق:** Wave 01 / Track C

**المبدأ الحاكم:** المنع افتراضيًا، وظهور metadata أو ارتباط المرفق بمالك لا يمنح حق تنزيل الملف.

## شروط القرار

يتطلب السماح اجتماع الشروط التالية: ممثل موثّق، صلاحية صريحة للعملية، علاقة معتمدة بسياق المالك، وتصريح بالتصنيف. ويُقيّم تنزيل المحتوى بصورة مستقلة عن عرض metadata. لا يوجد تجاوز إداري عام؛ المدير يحتاج صلاحية العملية والتصنيف كغيره. ممثل worker/service مقيد بغرض ومهمة محددين ولا يرث صلاحيات المستخدم.

## مصفوفة النتائج المتوقعة

الرموز: **A** سماح، **D** منع، **C** سماح مشروط بصلاحية صريحة وتطابق السياق والتصنيف، **N/A** غير متاح لهذا النوع من الممثلين.

| العملية | المكلف المالك | مكلف غير مرتبط | موظف مكلّف | موظف غير مخول | مدير بصلاحية صريحة | مستخدم تقارير/قراءة | مجهول | Worker محدد المهمة |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| طلب نية رفع | C | D | C | D | C | D | D | D |
| تسجيل اكتمال الرفع | C | D | C | D | C | D | D | C |
| عرض metadata | C | D | C | D | C | C | D | C |
| سرد الإصدارات | C | D | C | D | C | C | D | C |
| طلب تنزيل | C | D | C | D | C | D | D | D |
| إنشاء إصدار مصحح | C | D | C | D | C | D | D | D |
| أرشفة | D | D | C | D | C | D | D | C |
| ربط/فك ارتباط بمالك | D | D | C | D | C | D | D | D |
| مرفق شديد الحساسية | C | D | C | D | C | D | D | D |
| استدعاء service/repository متجاوزًا UI | نفس القرار | D | نفس القرار | D | نفس القرار | حسب العملية | D | حسب المهمة |

`C` لا تعني السماح بالصفة وحدها. كل حالة إيجابية يجب أن تثبت permission + owner context + classification clearance. للمكلف المالك لا تتاح العمليات الداخلية، وللموظف المكلّف لا تتاح الملفات شديدة الحساسية دون clearance منفصل.

## حالات الاختبار الإلزامية

1. يرفض غياب actor أو permission أو owner context أو classification clearance.
2. يسمح بعرض metadata ولا يسمح تلقائيًا بتنزيل المحتوى لنفس actor.
3. يرفض الاعتماد على owner link وحده.
4. يرفض أي admin بلا الصلاحية الصريحة للعملية.
5. يرفض تعديل إصدار تاريخي؛ التصحيح ينشئ رقم إصدار جديدًا مرتبطًا بسابقه.
6. يرفض فك ارتباط أو hard delete لسجل أرشيف دائم.
7. يرفض worker إن لم تتطابق المهمة والغرض والعملية.
8. يعيد أخطاء آمنة (`ATTACHMENT_ACCESS_DENIED` أو `ATTACHMENT_NOT_FOUND`) بلا storage key أو checksum أو تفاصيل وجود الملف.
9. يطبق القرار نفسه عند استدعاء controller أو service أو repository مباشرة في الاختبار؛ لا تعتمد الحماية على إخفاء زر في UI.
10. لا تستعمل الاختبارات أسرارًا، شبكة، Supabase، قاعدة بيانات، bucket أو ملفات حقيقية.

## طبقات الاختبار

- **Unit:** evaluator نقي يختبر كل بُعد من القرار وحفظ lineage.
- **Application integration scaffold:** استدعاء بوابة الخدمة in-memory وإثبات المنع تحت UI.
- **Adapter contract (لاحقًا):** mock storage فقط؛ يثبت أن provider لا يُستدعى قبل نجاح التفويض.
- **HTTP integration (بعد Track B):** تثبيت status/error contract دون كشف metadata حساسة.

ملف الاختبار الآلي المرافق: `apps/api/test/attachment-authorization.security.test.ts`. وهو harness مستقل مؤقت؛ يستبدل باستيراد evaluator الفعلي بعد دمج Track B مع الحفاظ على الحالات نفسها.
